Playable alpha (v0.4.0): http://ai-4-vc-mission-evade.s3-website-us-east-1.amazonaws.com/
Runs in a desktop browser (Chrome tested). Controls: WASD/arrows move, Space throws a decoy, Esc pauses, ` opens the developer view.

1. Where we are

Mission Evade is a top-down 3D stealth game (Three.js). The player crosses a guarded facility to the exit. Pillars: Pathfinding & Navigation (our own A*), NPC AI / Behavior Trees (guards: Catch › Chase › Notice › Investigate › Patrol), and Procedural Generation (planned below). Between runs, an LLM retunes the guards from run memory, and every suggestion goes through our own validator. The alpha adds the full game loop around this core: menu → mission of 5 security levels and 3 lives → win or loss → back to the menu.

3. Release notes: v0.4.0-alpha (changes since the midterm, v0.3.0)

New features

  • Full game loop. Main menu → run ⇄ pause → run result → mission complete / mission failed → menu. A state machine (js/game.js) runs it and refuses illegal moves between screens.
  • Missions: 5 security levels and 3 lives. An escape clears a level, and a catch costs a life. A mission in progress survives a page reload (Continue mission).
  • Reinforcements: each level above 1 adds one guard (up to 6). New guards are posted where run memory says the player was caught, spotted or walks most. They are never posted near the start or exit, never in view of them, and never crowded together, so the exit can always be reached.
  • Exit lock: the exit opens only while every guard is on patrol. It turns red while any guard is suspicious, searching or chasing.
  • Ringing decoy: a decoy rings for 6 seconds and pulls guards in to search while the player slips past.
  • New map: smaller (16×12, down from 24×16) with two separate routes to the exit, and redrawn guard routes.
  • Menus and HUD: main menu (start/continue, new mission, how to play, settings), pause menu, and mission-end stats. The HUD shows level, lives, objective, a detection meter (Hidden / Seen / Spotted!) and guard messages.
  • Developer view (behavior tree, learner, memory, debug map, stress test) is hidden from players. Toggle it with `.
  • Hosted LLM hook: a deployed Lambda proxy can serve as the default learner, so visitors need no API key.
  • Tests: 15 new automated tests, 40 in total, all passing. They include a bot that plays a full mission against the real simulation.

Bug fixes

  • Pressing R during learning started the next run with old guard settings. Restart now works only during a run.
  • A late LLM reply could overwrite memory that had just been reset. Late replies are now dropped.
  • One error inside a frame froze the game for good. The loop now survives, logs the error and pauses.
  • After a GPU reset (lost WebGL context), the game drew into a dead context. It now pauses until the context returns.
  • Space and arrow keys were blocked from scrolling the page outside of play. They are now captured only during a run.
  • Browsers could cache a mix of old and new modules after an update. The server and S3 deploy now send no-cache.
  • A focused top-bar button was pressed again by Space while throwing a decoy.

Known issues

  • Restarting a run (R) costs no life, so a spotted player can restart to avoid a catch. Fix planned for Week 11.
  • The LLM proxy is not deployed yet. The hosted build uses the built-in learner unless a key is entered in the developer view. Planned for Week 10.
  • No sound in this build (Week 11). Only one hand-built map, no procedural maps yet (Weeks 10–11).
  • Levels 4–5 (5–6 guards on a small map) may be too hard. Balancing follows the playtests.
  • A decoy thrown near the exit keeps it locked for about 6–9 seconds. This is intended, but may need tuning.
  • Run memory from the midterm map is not carried over to the new map.
  • Tested only in Chrome (desktop and mobile emulation). Safari and Firefox are untested. A missing favicon causes a harmless console 404.
