Mission Evade

Assignment 6: Feature Complete & Peer Playtesting

Ashish Lakra (al2112), Joel James (jj1176)

Mission Evade is a 3D stealth game. The player sneaks past guards to reach an exit. After each run, an AI model (LLM) studies how the player moved and adjusts the guards.

Build (v0.6.0): download zip from GitHub. To run: unzip, open start.bat (Windows) or run ./start.sh (Mac, Linux), then go to http://localhost:8000. Needs Node.js or Python 3. Source code: github.com/ashishlakraa/mission-evade. Note: our website on Amazon S3 is currently unavailable (error 403), so this build runs locally.

Release Notes: changes since the Beta (v0.5.0)

Final feature integrations

  • Sound: footsteps, guard alerts, chase heartbeat, decoys, exit lock, and win and lose sounds. Closer guards sound louder. Players can mute (M) or change the volume.
  • 3D models and textures: animated player and guards, a sliding exit door, and matching floor, wall and door textures. We generated all of them with our own script.
  • Restarting costs a life: restarting, leaving or reloading during a run now costs one life. Before, players could restart for free to avoid being caught.
  • Instructions for new players: a short briefing explains the goal, rules and controls. Hints appear during the first run.
  • Easier late levels: each level adds a guard. From level 3 the added guards are weaker, and levels 4–5 give extra decoys.
  • Works offline: everything except the AI model runs without internet. Tests: 74 automated tests pass (20 new).

Bug fixes

  • The AI model used in the Beta (Qwen2.5-7B) is no longer offered by any Hugging Face provider. We now use Qwen3.5-9B, also an open model.
  • Graphics memory grew with every restart; it now stays constant.
  • The game no longer freezes briefly when the first decoy is thrown.
  • The touch buttons no longer run off the screen when a phone is held sideways.
  • Browser shortcuts such as Ctrl+R no longer trigger game actions.

Features we cut

  • A server to share our AI access key (planned in Assignment 4). We removed it in the Beta but did not mention it in Assignment 5. The key is entered on the /admin page instead. Without a key, the game uses a simple rule-based learner.
  • Randomly generated maps (already reported in Assignment 5).

Known issues

  • The website is offline, and levels 4–5 are still hard. The AI model usually takes 5–25 seconds between runs, sometimes longer. An accidental reload costs a life. Not yet tested on a real iPhone or Mac.

User Study Results: simulated pilot

Status. We have not yet held sessions with classmates, so the 5-subject requirement is not met. Instead, this section reports a trial with five simulated players: programs we wrote, not people. Classmate sessions are planned for Nov 25–27.

Methodology

Each simulated player acted out one type of player in the real game, in a real web browser. All guard updates came from the AI model (Qwen3.5-9B). We recorded results, errors, frame rate and the on-screen messages shown. Programs cannot think aloud or rate the controls, so we have no quotes and no ratings out of 10.

Overall result: all 41 automated checks passed in Chrome's engine (Chromium) with no errors. All except the long careful-player test were repeated in Firefox and WebKit (Safari's engine), and all 36 checks passed in each.

Action items for Assignment 7 (to be updated after the classmate sessions)

  1. Make level 5 easier. The careful player was caught there 5 times in a row.
  2. Make the first level gentler. The first-timer was caught in all 9 runs.
  3. Move the first added guard further from the start. The rusher was caught within 3 s on level 2.
  4. Make guards easier after quick or repeated catches. The game already stops them getting harder, but in 7 of 19 such cases the AI model left them just as hard.
  5. Shorten the wait between runs. The first-timer waited up to 26 s for the AI model.
